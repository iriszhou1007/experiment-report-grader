# Experiment Report Grader

Keep student files local and the instructor in control. The user's current instructions take precedence over defaults in this skill.

## Defaults and authorization

- Reuse compatible settings from the current batch or the newest sibling batch: rubric, inspection mode, score increment, OCR mode, and text budget. Tell the user what was reused without pausing.
- If no saved settings exist, use the default rubric, text_only, whole-number scores, automatic OCR, and dynamic text budgets. State these defaults and continue unless the user explicitly asks to review or change them first.
- Warn before a first `prepare` on a screenshot-heavy batch when OCR is enabled: local OCR takes roughly 2.5-3s per candidate page, so a large batch can spend 20-30 minutes there. It prints `[ocr] …` progress per report and costs no API tokens.
- Do not ask for a batch name when it can be derived from the report-folder name. Do not request separate confirmation for extraction, draft grading, HTML, or Excel because these steps are reversible and do not modify source PDFs.
- Never change a source PDF until the user explicitly approves the named report or batch. This is the only mandatory approval gate.
- Before an approved write-back, preserve an immutable original. Reapprovals regenerate from that backup so feedback pages never accumulate.

## Workflow

Use `scripts/batch_pipeline.py` rather than rebuilding extraction, chunking, validation, HTML, or Excel logic manually. Run `python3 scripts/batch_pipeline.py doctor` once per machine, and again whenever a phase fails on a missing external piece: several dependencies fail late rather than at startup (on macOS and Linux a missing OCR helper degrades quietly to the visual queue; a missing `reportlab` breaks the approved write-back only after the whole batch has been reviewed; on Windows a missing Tesseract stops `prepare` outright). `doctor` reports every external path together with the layer that resolved it, plus an `ocr engine` row naming the local engine, and `doctor --self-test` additionally runs the artifact writer on synthetic reviews and checks its panel payload, batch notices and score offset. Read [references/grading-workflow.md](references/grading-workflow.md) only when changing OCR/budget behavior, recovering an incompatible batch, or debugging the compact decision format. Read [references/local-ocr-setup.md](references/local-ocr-setup.md) when OCR reports `unavailable`, when a batch's screenshots are not being recognized, when setting up a new machine, or when you need to tell the user which local OCR engine their machine will use; `scripts/setup_local_ocr.sh` generates the shims it describes. Read [references/portability.md](references/portability.md) when moving the skill to another machine or agent host, or when an external path fails to resolve.

1. Run `prepare` with the report folder, confirmed rubric, inspection mode, and score increment. The folder name is the default batch name. Preparation fingerprints shared course-template instructions and routes each report to fast, standard, or detailed grading. If it reports `reused_settings`, tell the user which settings were inherited from an earlier batch: an inherited text budget silently changes how much evidence each report gets.
2. Grade from `grading-input-*.md`. It carries the confirmed rubric, the source filename, and a per-report `coverage:` line stating which pages were included, omitted, or truncated. In smart mode, inspect the listed cropped visual assets first and open the named source page only when no usable crop exists, the crop lacks context, or the coverage line flags evidence the packet could not carry. OCR and extracted text do not preserve layout: never infer alignment, readability, table placement, image absence, or screenshot presentation from their serialized order. A deduction marked `requires_visual_evidence` requires opening the smallest relevant source-page set.
3. For the default evidence-deduction rubric, fill `d` with confirmed deduction facts and let the program calculate `s`; also fill overall comment `c`, item reasons `i`, item evidence `e`, and visual evidence `v`. Each deduction contains `item`, `rule`, a report-unique `fact`, `reason`, `certainty`, `evidence`, and `visual_evidence`. Apply only a printed rule. If no listed defect is clearly confirmed, use an empty `d` list and allow the full score; never invent a weakness merely to avoid a high score. A deduction above 2 points requires `certainty=confirmed` plus explicit page evidence; truncated or uncertain evidence cannot support it. Never charge one fact under two items or combine rules marked mutually exclusive. Legacy fixed-band rubrics still use `r` plus `s`. Then make a second blind pass into `recheck-*.jsonl` without inspecting or copying the first pass.
4. Run `finalize`; it validates both ledgers, calculates scores, and writes `regrade-audit.json`. A total difference above `max_regrade_delta` creates review artifacts marked `adjudication_required` instead of suppressing the whole batch. The panel may save these drafts, but approval, batch approval and PDF write-back remain blocked until the teacher explicitly confirms the disputed report's current score. Never average the two totals. The default rubric also guarantees a published batch mean of at least 90 through the smallest uniform capped score offset; raw evidence scores remain visible beside adjusted scores. A larger course adjustment may still be requested with `--score-offset`.
5. Use `status` to resume. Use `clean` only after verifying outputs.

For a custom rubric that needs the same stability guarantee, prefer item-level `deduction_rules` with fixed `points`, observable descriptions and bounded `max_occurrences`. Use `exclusive_with` when a task-level deduction replaces narrower omissions, and add `requires_visual_evidence` only when the fact depends on layout, legibility, image presence or placement. `grading_notes` travel into the grading packet and should carry task requirements, question ids, answer anchors and accepted environment-dependent variants. The optional root settings `minimum_minor_deduction`, `minimum_report_deduction`, and `maximum_minor_items` impose a hard minimum only when the teacher explicitly wants one; leave them absent for evidence-only grading. Without confirmed answer anchors, reserve three-point correctness deductions for direct contradictions or unquestionably unanswered requirements. Legacy fixed bands remain readable.

When grading “实验1：Web服务器搭建与HTTP协议分析”, use `assets/rubrics/experiment-1-web-http.json` and read [references/experiment-1-web-http.md](references/experiment-1-web-http.md). The canonical guide is [assets/guides/experiment-1-web-http.pdf](assets/guides/experiment-1-web-http.pdf). Version v6 retains IIS OR Apache (30), HTTP (35), Conditional GET (25), and report process (10). If both servers are shown, choose the complete evidence-backed implementation favorable to the student; do not add credit or deductions for the unselected alternative. RPT-1/2/3/4 come from section 7 “实验报告要求” (PDF page 10), including task 2's 10 and task 3's 4 analysis questions and two reflections. RPT-5 is an explicit teacher supplement: every submitted experiment screenshot needs a figure number, a body-paragraph reference by that number, and a description; record distinct problem screenshots in one `screenshot_documentation_issue` with a `figures` array in item 4. Each screenshot costs 2 points; 1/2/3 or more cost 2/4/6, with no extra charge for more defects on the same image. Each figure records its original-page locator `p.N#imageK`, missing `requirements` and `reason`, with that page visually checked; the program counts and caps at 6. Missing whole-task images or analysis must not duplicate the same omission under figure documentation. Earlier task hints cannot add other requirements. Exact page-title wording, class/experiment labels, introductory paragraphs, root-path access proof, per-directive Apache explanations and other formatting remain outside deductions. Server thinking prompts remain optional. Do not reuse v5 or earlier ledgers or a generic sibling rubric; prepare a new v6 packet before regrading.

For experiment-1 v6, finish all other deduction checks first, including screenshot documentation. Only if that ledger is empty, inspect original PDF pages for a normal multi-line Chinese prose paragraph whose first line has no indentation relative to following lines. Titles, question prompts, lists, code, tables, captions and text inside screenshots do not count; unclear or single-line paragraphs do not prove no indentation. Do not require an exact indentation width. A confirmed defect may select `body_first_line_indent_missing` for 3 points in item 4, with visual page evidence. Its `only_if_no_other_deductions: true` flag makes it the sole deduction across all items; the program rejects stacking in either order. When any other deduction applies, omit this conditional rule, not the substantive defect. Correct indentation and no other defects still permit 100.

For this rubric, every deduction (even 2 points) needs explicit `certainty=confirmed`. Use `fact=rule` exactly; for a rule with `requirement_ids`, add `requirements` containing all affected ids, in one grouped entry. Other general issues stay fixed at 2 points per category, not per wrong answer; the screenshot rule counts distinct images at 2 points each, capped at 6; a whole-task rule replaces its narrower rules. An absent second network GET is not an absent second visit when the student observed, checked and explained it. Keep the blind recheck enabled. With `recheck_fact_consistency`, any difference in deduction categories, affected requirements or identified problem screenshots requires teacher adjudication even at a zero total delta. The panel shows both ledgers and cited pages. Stable calculation is guaranteed for identical facts, not identical model judgments.

The experiment's `distribution_target` audits whether **more than 80%** lie in 92–98, separately for raw and published scores. It is a draft-generation snapshot, not a quota or a reason to invent/suppress deductions. Full credit is allowed; never cap at 98 or force a minimum deduction. Do not promise that this fraction or a repeat-score bound has been achieved without real-report tests; synthetic tests prove validation/calculation only. Preserve the existing transparent average-floor policy independently.

For interactive review, always start the local review service and open its `http://127.0.0.1:8765/` URL. Do not present a `file://` HTML page as the primary review interface; static HTML cannot directly save JSON, Excel, or PDFs and is only an offline/archival fallback.

The service locates the skill as `<workspace>/experiment-report-grader` by default. When the skill lives elsewhere — a git checkout, for instance — pass `--skill-dir`, and set the scratch root with the `EXPERIMENT_REPORT_GRADER_WORKSPACE` environment variable so batch work directories stay beside the batch data. It needs the `--python` interpreter and nothing else: the panel, the workbook and the write-back are all produced by this skill's Python scripts:

```bash
export EXPERIMENT_REPORT_GRADER_WORKSPACE=~/Downloads
node ~/git/experiment-report-grader/scripts/review_server.mjs \
  --workspace ~/Downloads --skill-dir ~/git/experiment-report-grader \
  --python "$(command -v python3)" \
  --port 8765 --run-id 实验4 --pdftoppm <poppler bin>/pdftoppm
```

Readers of this file on a new machine should read [references/portability.md](references/portability.md) instead of copying the paths above: every external path (signature template, handwriting face, interpreter, Node, OCR helpers) resolves as flag → `EXPERIMENT_REPORT_GRADER_*` environment variable → `config/local.json` → bundled asset → platform probe, and `doctor` prints which layer answered each one.

To publish or move the skill, run `python3 scripts/package_skill.py --out dist/ --verify` (it writes a `.zip`, a `.tar.gz`, and a `SHA256SUMS` file, then checks the extracted copy). The zip is the distribution format: the receiving machine needs no git and no network, only the archive. `python3 scripts/install_skill.py` detects which agent hosts are present and links the skill into the directories they read (`--dry-run` first if you prefer), and `node scripts/verify_host_registration.mjs --install` proves the registration by running the host's own discovery code. The roots for every host live in `skill.json`.

## First run on a new machine

Follow this in order. Nothing here modifies a source PDF, and every step is safe to re-run.

0. **Settle the interpreter.** Run `python --version`, then `python3 --version`; whichever answers is the one to use (Windows: `python` or `py -3`; macOS/Linux: `python3`). Commands below are written with `python3` — substitute the one that answered, and prefer a full path over a bare name when the machine has several interpreters. On Windows also run `chcp 65001` (or set `PYTHONUTF8=1`) so Chinese output is not mangled.
1. **Read the facts before changing anything:** `python3 scripts/bootstrap.py --json`. It reports missing Python modules, the per-machine assets (signature template, handwriting face, OCR helpers, pdftoppm) with the layer that resolved each one, whether the write-back is currently possible, and a **local OCR** section naming every engine this machine has. Every machine differs — macOS ships Vision, Windows expects Tesseract, a conda environment may hold rapidocr — so read that section and tell the user which engine their machine will use rather than assuming.
   On Windows, do not equate a C-drive miss with no installation. The resolver checks configured paths and PATH, then performs a bounded search of common installation directories on every local fixed drive (not network/removable drives or a recursive whole-disk search). It tests executable startup/version and Tesseract's `chi_sim` + `eng` language list. If unresolved, report the searched scope/limits and ask for the existing full executable path before suggesting installation; do not claim a complete disk inventory. Explicit invalid flags/environment paths are errors, not permission to silently choose another install. `prepare` with OCR enabled requires both validated Tesseract and `pdftoppm`, and pins those paths for extraction. Run bootstrap/doctor after import; merely registering a skill does not run these checks. Read the Windows section of [references/local-ocr-setup.md](references/local-ocr-setup.md) for configuration examples.
2. **Install the Python dependencies** reported as missing, using the command bootstrap prints (it names the interpreter it checked, so the packages land in the environment the skill will actually use).
3. **Generate the OCR helpers** on macOS/Linux: `python3 scripts/bootstrap.py --ocr`, or `--ocr --with-vision` to also build the platform's own Vision engine. Vision is an explicit choice (`--ocr-engine vision`), not the default; `auto` uses the rapidocr shim. On Windows there is no shim generator — the helper script is bash — so its route is a real Tesseract install, and `prepare` **stops and asks for Tesseract** when it is missing (see step 6). Never run `scripts/setup_local_ocr.sh` on Windows.
4. **Configure the signature template**, which is per-machine and reported as `BLOCK` until it is. It is the teacher's own ink, so it cannot be generated, downloaded or substituted: ask the human for the file. Four ways to supply it are listed by `bootstrap.py`; `python3 scripts/bootstrap.py --write-config` records it in `config/local.json`.
5. **Register with the hosts on this machine:** `python3 scripts/install_skill.py --dry-run` first to see the target directories, then without `--dry-run`. Pass `--host workbuddy` (or `codebuddy`, `claude`, `dsh`, `codex`) explicitly when the host's directory does not exist yet, and `--copy` where symlinks and junctions are not possible.
6. **Verify:** `python3 scripts/batch_pipeline.py doctor` (every path plus its resolving layer, including an `ocr engine` row naming what this machine will actually use), `python3 scripts/batch_pipeline.py doctor --self-test` (the artifact writer's panel payload, batch notices and score offset across all three fixtures), and `node scripts/verify_host_registration.mjs` where Node exists.
7. **Smoke-test on a few reports** before a real batch: `prepare` → fill `decisions-*.jsonl` → independently fill `recheck-*.jsonl` → `finalize` → `scripts/dry_run_annotation.py` (dry run writes only to a temporary directory).

What the agent may do on its own: steps 0–3, 5–7, and reading step 1's report. What it must not do: invent or placeholder the signature template (step 4), install system-level software (Tesseract, poppler, Node, Python itself) without asking, or run `scripts/setup_local_ocr.sh` on Windows. Report those and stop.

Approving a whole reviewed batch is also possible without the panel: `scripts/approve_batch.py` runs the same write-back per report and rebuilds the review artifacts once at the end.

For an approved PDF mutation, read [references/pdf-writeback.md](references/pdf-writeback.md). The teacher-signature template is a per-machine asset and is deliberately not packaged: `bootstrap.py` reports it as `BLOCK` until it is configured (flag, environment variable, `config/local.json`, or a PDF under `assets/signature/`), and the write-back refuses rather than skipping the signature. Grading, review and Excel work regardless. An approved write-back both prepends the feedback sheet and stamps the review marks onto the student's own pages: a red checkmark on every page of student work **before** the 指导老师评议 page (that page is the signature page and is left unmarked), the teacher's signature ink on it, and the reported grade written into the `成绩评定` field where the form previously carried a default `100`. It verifies its own output and refuses to write when a mark would land on existing content. Read [references/review-schema.md](references/review-schema.md) only when debugging review JSON.

## Grading calibration

- **Score by requirement, not by capture value.** Give credit for data found in prose or readable screenshots; when a requirement asks for explanation, raw packet screenshots alone do not supply it. A Wireshark capture holds hundreds of values; the student need not transcribe them all. Extra frames and field readouts are not defects. Counting transcribed-versus-visible values is not a measure of anything.
- Base deductions on the confirmed rubric and report evidence. Extraction warnings are review flags, not automatic deductions.
- Check each requirement independently before deduplicating deductions; a deduction under one rule does not excuse skipping another check. When the same fact is already charged elsewhere, briefly identify that rule in the existing item comment rather than charging it again.
- Accept every valid form of an answer. "第一个 Ping 包返回的准确时间" is answered by a round-trip time (`2.222ms`) as legitimately as by a wall-clock stamp, and a question whose text sits inside a screenshot may be answered in the prose below it. Before recording a gap, check for a different-but-equivalent answer rather than a missing one.
- Every page of every report reaches the packet, but a page may still be cut short. Read the `coverage:` line first: a page listed as omitted or truncated is not evidence that the student left it blank.
- Text following an OCR marker came from image recognition. Never deduct for a term, spelling or number that only looks wrong there.
- OCR can recover words but not page geometry. A layout or legibility deduction that selects a visually gated rule requires opening the smallest relevant set of source pages and recording them in `v`; this is an on-demand check for that deduction, not a reason to visually review the whole batch.
- Completed core work with usable evidence and basically correct conclusions should receive high marks. The default rubric deducts only clear, listed defects and permits 100 when none is confirmed. The batch-level 90-point floor is applied transparently as a uniform offset, never by inventing or suppressing report-level deductions.
- Keep one concise, specific student-facing overall comment. Ensure item scores stay within their maxima and sum exactly to the total.
- Always fill `e` with the pages each item score rests on. A score the instructor cannot spot-check is a score they have to re-derive by hand.
- **The grader judges which observable deduction facts apply; the pipeline deterministically calculates the resulting score.** This removes free choice inside a broad range but cannot remove disagreement over whether a fact is present. For the default rubric, fill `d`, `i`, `e`, and `v` as applicable, then complete the blind `recheck` pass. A total difference above 2 marks that report `adjudication_required`: `finalize` still generates the review artifacts, while every approval path refuses the report until the teacher acknowledges the disputed score. Adjudicate the changed facts from their cited pages rather than averaging. The comparison measures *disagreement*, not accuracy: a packet that hides needed text can make both passes agree on the same wrong call, while a complete packet can expose different judgments. When comparing releases, still diff the packets first (see [references/grading-workflow.md](references/grading-workflow.md) and the historical measurement in [references/regrade-gate-report.md](references/regrade-gate-report.md)).

## Persistent outputs

Create one `<batch-id>_批改结果` folder under the source-report folder. Keep only the Excel workbook, review HTML, `index.md`, `批次信息.json`, `复评分差异审计.json`, `reviewjson/`, and immutable approved originals under `原始数据/`. Temporary extraction, OCR, and decision files stay outside this result folder.
