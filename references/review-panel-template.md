# 评审面板模板

评审面板的唯一 HTML 来源是 [`../assets/review-panel-template.html`](../assets/review-panel-template.html)，由 [`../scripts/build_review_html.py`](../scripts/build_review_html.py) 将当前批次数据注入后生成。批次输出中的 HTML 是生成产物；需要复用或调整界面时，修改资产模板，再用生成脚本重建。

## 当前模板包含

- **批次区**：报告目录、批次名称、预检摘要和批次级提示。检查模式在评分开始前由教师选择，不放在评分后的审核面板里。
- **报告列表**：姓名、学号、分数和状态；报告筛选保持单一“待审核”状态，常规待审报告与双评差异报告都在其中；有差异的报告额外显示“双评有差异”标识。差异确认门槛继续拦截批准和写回，但不作为另一种报告状态。同一学生的 PDF 与 DOC/DOCX 旁件不重复列出。预检提示另起一行，避免挤压身份和状态信息。
- **评分区**：姓名、学号、主题和报告路径；滚动评分时固定显示总分；分项评分和综合评语；有双评差异的报告须由教师核对并确认后才可批准。此类报告的写回按钮直接打开裁决确认弹窗，不要求事先勾选页面底部选项。
- **源 PDF 区**：可切换 PDF 展示宽度，并能新窗口打开源文件。
- **写回选项**：原页手写分项评语、逐页画勾、教师签名、成绩栏手写分数、反馈页首页/末页位置；普通报告的连续审批使用独立开关。双评差异弹窗内另有“连续裁决”开关，仅作用于当前批次和浏览器会话；开启后后续每份仍须点击明确标注的裁决写回按钮，前端才向服务端提交该报告的裁决确认。
- **操作区**：保存草稿、批准并直接写回 PDF、标记需重新提交。按钮保持横向网格；错误或保存结果显示在按钮下方，长消息不能挤压按钮。
- **补交流程**：教师手动确认收到新 PDF，或取消误标；重新评分从新证据开始。Word 旁件提示上传 PDF 后重新加载批次。
- **批次清理**：批次栏单独显示“清理评分暂存文件”按钮和原因/状态文字。按钮初始化为禁用；审核服务加载后通过 `GET /api/cleanup` 获取实时状态，不在 HTML 里猜测是否可清理。评分、盲复核、裁决和教师审核全部完成，且正式结果文件存在后，才启用按钮。服务端必须同时确认：批次信息可读且已完成、待处理数为零；存在评分记录且每份都已审核、没有待补交报告或未确认的双评差异；`<报告目录>/<批次名>_评分暂存/` 是存在的普通目录、路径与批次记录一致且没有越出当前报告目录；其中的 `grading-manifest.json` 与当前批次 ID 和结果目录匹配；成绩表、审核面板和批次信息等正式结果文件均非空。否则在按钮旁显示具体阻塞原因，例如“没有找到本批次的评分暂存目录”或“缺少匹配当前批次的评分清单”，并保持禁用，不能据此自动搜索或清理其他位置的文件。
- **清理确认与保留项**：按钮可用后，操作前列出 skill 管理的工作目录、文件数和占用空间，并要求教师确认已经核对成绩表和 PDF 写回结果。点击后服务端再次执行同一套资格检查，只清理 `<报告目录>/<批次名>_评分暂存/`。不删除源 PDF、正式结果目录、评分记录、差异审计或 `原始数据/` 备份。

## 复用约定

- 保持三个数据占位符各出现一次：`__REVIEWS_JSON__`、`__BATCH_NOTICES_JSON__`、`__PREFLIGHT_JSON__`。写出器会校验它们的数量，并安全转义批次数据。
- 只把静态结构、样式和交互放在 HTML 模板；学生、批次、分数、预检结果等动态内容由写出器注入或由审核服务读取。
- 批次清理是前后端共同功能：按钮、布局和状态文案容器属于 HTML 模板；资格检查、文件清单/大小、确认后的删除及路径安全校验属于 `scripts/review_server.mjs` 的 `/api/cleanup`。修改任一侧时同步检查另一侧，避免出现按钮存在但状态无法更新、或仅靠前端放行清理的情况。
- 新状态需要同时检查状态文案、列表样式、状态筛选、详情动作、成绩统计和批准/写回门槛，避免只改颜色或标签造成状态不一致。
- 响应式布局需覆盖窄屏；长错误信息应独立换行，不得压缩或竖排操作按钮。
- 每次改模板后，从真实批次或合成数据重新生成面板，至少检查脚本语法及窄屏/宽屏布局。
