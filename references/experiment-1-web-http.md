“网站根目录记录”仍须有，但不等于必须展示访问根路径。只按第7节检查姓名、学号和地址栏，不沿用旧版“两服务器同页”等要求。

## 二、分值与固定扣分

四个计分项：所选Web服务器30、HTTP请求响应分析35、Conditional GET 25、独立实验过程与报告质量10。原两个服务器的15+15合并为所选服务器30分。

每项从满分起评，只扣下列确认的事实；分项最低0分，程序计算总分。

| 明确问题 | 固定扣分 | 依据与计入位置 |
|---|---:|---|
| 所选服务器配置记录与页面访问结果整体未提供 | 5 | RPT-1；第1项；替代该项其他扣分 |
| 所选服务器必要记录、软件来源/启用方式或URL文件关系明确缺失，或与自身结果直接矛盾 | 2 | RPT-1；第1项；合并全部问题一次 |
| 自建页面姓名/学号，或已有访问截图的地址栏等必需内容明确缺失 | 2 | RPT-1；第1项；合并一次 |
| 所选服务器页面访问截图完全没有 | 3 | RPT-1；第1项 |
| 某组协议抓包与分析整体未提供 | 8 | RPT-2；对应HTTP或Conditional GET项；替代该项其他扣分 |
| 某组题目整体没有必要文字回答/分析，包括只有图无解释 | 4 | RPT-2；对应协议项；替代局部分析问题 |
| 某组有分析，但必答题明确完全未答、核心判断直接矛盾，或整组完全没有具体报文依据 | 2 | RPT-2；对应协议项；所有一般问题合并一次 |
| 某组有文字分析，但整项完全没有抓包截图 | 3 | RPT-2；对应协议项 |
| 要求的版本或环境记录明确缺项 | 2 | RPT-1；第4项，合并一次，不检查未选服务器 |
| 没有至少一项资料及来源，或没有说明具体帮助 | 2 | RPT-3；第4项，合并一次 |
| 完全没有问题排查/验证，也没有关键配置验证 | 2 | RPT-3；第4项 |
| 两道小结中有题明确完全未回答 | 2 | RPT-4；第4项，合并一次 |
| 已提交实验截图缺少图号、正文按图号引用或文字描述 | 每张2，最高6 | RPT-5；第4项，按不同问题截图计数，同图多个问题不重复扣 |
| 无其他任何扣分时，普通中文正文段落首行明确没有缩进 | 3 | RPT-5；第4项；须看原页，且必须是整份报告唯一扣分 |

同一事实不重复扣分。截图缺失不能再推断为身份缺失或无证据分析；缺失的题目不能再扣“报告完整性”。所选服务器整项未做，不再因对应服务器环境未写重复扣。同一来源缺失不在第1项与第4项重复扣。只缺第二次访问的分析内容，归入Conditional GET一般问题合并扣2分，不再另设4分项目。

资料查阅（SOURCE/HELP）、排查验证（VERIFY）、两道小结（R1/R2）分别核对，再处理去重；一项已扣不能成为跳过另一项的理由。同一资料帮助缺失不在RPT-3和RPT-4重复扣，但若R2的对外服务核验与资料帮助/困难均完全未答，仍有独立的R2未答事实，不能因HELP已扣而漏检；RPT-4理由应指出该独立事实，不再次单扣HELP。

接受全文其他位置的等价实质回答。R1不要求“原以为……后来……”句式；一般抓包、配置或排障困难不自动等于查阅资料的困难。R1或R2已有相关实质回答，不因子要点不全按整题未答扣分；只有某题明确完全未答，才使用现有反思扣分规则。评分agent在现有第4项说明i中简述资料、验证、R1/R2的核对结果及依据页码；合格项可合并简写，因同一事实不另扣时简述规则归属，不新增字段或逐要点长表。

### 截图编号、引用和描述的检查口径

- 每张实际提交的实验截图都须有明确图号，并在正文段落中通过该图号引用、描述观察结果或用途。只有图下标题、只有“见图2”而无描述，或只有“如下图”而无编号，均未完整满足要求。
- 例如：图下标“图2 HTTP响应报文”；正文写“如图2所示，响应状态码为200，说明服务器成功返回了本次请求的目标页面。”其中数值应与本人的截图一致。
- 同一段落可引用多张图并分别说明，不强制每图单独一段。不因未单独重复截图中全部字段扣分。
- 按不同问题截图计数：1张扣2分、2张扣4分、3张及以上扣6分。相同截图同时缺图号、正文引用和描述也只扣2分；超过3张的问题截图不再增加扣分。
- 在一个screenshot_documentation_issue条目内用figures逐张记录原页定位、具体问题和缺失要素。定位写为p.N#imageK：N为原PDF页码，K为该页实验截图自上而下、同高从左到右的序号，不计页眉图标，不使用可能缺失的图号。各图定位不得重复，所处页均须已查看；顶层requirements是各图FIG-numbering、FIG-reference、FIG-description缺失要素的并集。
- 按原页先后记录最早三张已确认的问题截图即可封顶，不必为增加扣分继续查后续图；即使记录了更多，程序也只扣6分。规范化扣分依据及盲评对比只保留实际计分的最早三张，避免第4张及后续非计分观察造成同分争议。程序从不同图的数量计算扣分，不接受自行填一个未经逐图支持的数量。
- 只检查实际存在的截图；整项无图已扣分，不再扣不存在截图的图号/引用。若整组无文字分析已扣分，不再仅因同一缺文字重复扣FIG-description；独立缺图号或引用仍按不同问题截图计数，每张2分、最高6分。已有具体分析但缺图号/引用，只扣本项，不再据同一问题扣HTTP-figure-link或CACHE-figure-link。
- 图号是否存在、截图与段落的关系须看所指原页确认，不能以OCR未出现“图”字证明缺失。

### 首行缩进的条件性检查口径

1. 先评完其他全部规则，包括截图编排。只要整份报告已有任何其他扣分，缩进项不激活，不把它写入扣分清单。
2. 仅在其他扣分清单为空时查看原PDF，检查普通中文叙述性正文。至少一处可明确观察的多行段落首行与后续行左缘对齐、没有首行缩进，才扣3分一次。
3. 标题、题干、列表、代码、表格、图注和截图内部文字不作为普通正文。单行或看不清的段落不据此扣分；只检查“有无缩进”，不额外要求精确两个汉字。
4. 缩进规则标记only_if_no_other_deductions=true，程序拒绝它与任何分项的其他扣分叠加。它不是“总分封顶97”或“强制至少扣3分”。

## 三、判断参考，不增加扣分点

任务2、3是RPT-2明确引用的必答题，可查阅原题和以下参考；参考不是新增提交要求。

- 任务2（HTTP-Q1至Q10）：请求方法/资源/版本，响应版本/状态，双方IP/端口，语言偏好，可接受编码与实际编码，Accept与Content-Type，实际Last-Modified，Content-Length实体长度，目标网页对应关系，允许保持连接与实际TCP复用的区别。
- 任务3（CACHE-Q1至Q4）：首次请求及初始缓存状态，首次响应验证字段，再次访问实际是否产生请求及条件字段，实际结果与缓存验证/内容传输的关系。
- 动态数值以本人实验为准。缺字段而如实说明、第二次200或无网络GET且合理解释，均可成立；不得要求必须304、必须If-Modified-Since，或补造未出现的报文。
- 已有基本正确的核心回答，次要细节少、表述简短或未抄全字段，不扣。

## 四、证据与稳定性

- 所有扣分必须明确确认，写出对应RPT依据、事实、理由和页码。未列出的项目不扣。
- 未看到不等于没写：先排除报告其他位置、等价表达、截断及OCR问题。图片缺失、页面身份和整体结果缺失须核对相关原页。
- 仅按RPT-5检查明确的截图编排与条件性首行缩进；其他格式不独立扣分。证据看不清时只提示复核，不按未完成扣分。真实性疑点交教师，不凭相似报告或OCR身份推断造假。
- 程序按固定规则算分；截图按不同问题图计数封顶6分，其他普通类别最多扣一次。每条事实标识固定等于规则ID；有要求编号的规则列全涉及的编号。两遍盲评若扣分类别、涉及要求或具体问题截图不同，即使总分相同也交教师按证据裁决，不平均两分。
- 使用v6须重新prepare并评分，不能沿用v5及此前的草稿。旧测试结果保留为历史数据，不静默改写；以本文件和配套JSON为当前规则。
- 本次更新不等于已经证明真实报告评分稳定；仍须抽样复评验证。

## 五、高分与分布

没有明确问题允许100分，不设95/98上限，不设置无依据的最低扣分。仅确认无首行缩进、其他要求全部满足时为97分；已有一项一般问题扣2分时为98分，不再叠加缩进扣分。其他问题按既定规则累计。

超过80%的报告处于92-98是批次观察目标，不是个人扣分依据；不能为凑分布补造问题或撤销真实扣分。满分可能出现，应如实统计。

保留此前确认的发布均分不低于90设置：必要时使用透明的最小统一加分，原始分不改。原始分和发布分的区间占比分别统计；待裁决及教师修改前的统计不视为最终结果。
